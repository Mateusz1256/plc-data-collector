# Siemens S7

The S7 driver reads data blocks (DB), merkers (M), process inputs (I) and
process outputs (Q) from Siemens S7-300, S7-400, S7-1200 and S7-1500 CPUs and
compatible ones, over ISO-on-TCP (port 102). It never writes to the PLC.
Nothing in it is specific to one CPU: you choose the rack and slot and give
each Tag an address and a data type. The Panel can also create Tags from a TIA
Portal export.

> **Not tested on real hardware.** 0.5.0 S7 support has been verified only
> against the python-snap7 server, byte-level protocol fixtures and the
> bundled simulator. It has not been run against a real S7 PLC. The TIA Portal
> import calculates offsets from Siemens' documented memory layout; the
> tag-table column names are taken from TIA documentation, without an export
> from a real TIA Portal to test against. Before you trust an import, compare a
> few offsets with the Offset column in TIA, and read one known value. Please
> report any mismatch or a CPU that behaves differently.

Not supported: writing, connections by TSAP (LOGO!, S7-200, routed
connections), S7CommPlus and TLS, timers and counters, peripheral I/O
(`PIW`, `:P`), and DBs with optimized block access (see the checklist below).

## Connection

The endpoint is `tcp://host:port` (IPv6 hosts in brackets). The Panel shows
Host and Port (default 102) as two fields. `timeout_ms` is the timeout for
opening the connection and the default timeout of a read.

`protocol_options` of a Connection (all optional):

| Option | Panel label | Values | Default |
| --- | --- | --- | --- |
| `rack` | Rack | 0 to 7 | 0 |
| `slot` | Slot | 0 to 31 | 1 |
| `max_gap` | Max gap to read through (bytes) | 0 to 256 | 16 |

`max_gap` is under "Advanced" in the Panel. Unknown options are refused.

The usual slot is 1 for an S7-1200 and S7-1500, and 2 for most S7-300 and
S7-400 CPUs. The rack is 0 for all of them unless the CPU sits in an extension
rack.

There is no block size option: the limit comes from the PDU size the CPU
agrees to when the connection opens. "Test connection" shows that size and, if
the CPU answers the query, its order number, for example
`PDU 240 bytes, CPU 6ES7 ...`. A CPU that does not answer the query does not
fail the test. The driver asks for the CPU once, the first time it connects.

## Checklist for S7-1200 and S7-1500

These CPUs refuse outside reads by default. In TIA Portal:

1. Open the CPU's properties, "Protection & Security", "Connection mechanisms",
   and tick "Permit access with PUT/GET communication from remote partner".
2. For every DB you read, open its properties, "Attributes", and clear
   "Optimized block access". Optimized DBs have no fixed offsets, so the
   protocol cannot address them.
3. Compile and download the hardware configuration and the changed DBs.

Merkers, inputs and outputs need only step 1.

## Tag address

A Tag's `address` is stored in one canonical form, without `%` and without a
size letter: `DB<n>.<byte>`, `M<byte>`, `I<byte>` or `Q<byte>`, and
`DB<n>.<byte>.<bit>`, `M<byte>.<bit>`, `I<byte>.<bit>` or `Q<byte>.<bit>` for
the data type `bool`.

| Area | Byte form | Bit form |
| --- | --- | --- |
| Data block | `DB10.4` | `DB10.4.0` |
| Merkers | `M20` | `M20.3` |
| Inputs | `I0` | `I0.3` |
| Outputs | `Q8` | `Q8.1` |

The DB number is 1 to 65535, the byte 0 to 65535 and the bit 0 to 7 (bit 0 is
the least significant). A bit address is required for `bool` and refused for
every other type. The address plus the Tag's span must not pass byte 65535.
The size lives in `data_type`, so types without a STEP7 size letter (`lreal`,
`string`) need no special case.

## STEP7 input and display

Where you type or paste an address (the Panel's "Paste address" box, the CSV
paste and the TIA import), these forms are accepted and converted to the
canonical form, in upper or lower case: `%DB10.DBX4.0`, `DB10.DBB4`,
`DB10.DBW4`, `DB10.DBD4`, `%MW20`, `MB20`, `MD20`, `M20.3`, `%I0.3`, `IW8`,
`QB4`. The German letters `E` (inputs) and `A` (outputs) work too. A size
letter that contradicts the data type, such as `DB10.DBW4` with `real`, is an
error and is never fixed silently.

The Panel shows the STEP7 form that fits the data type, so addresses look
as they do in TIA:

| Stored | Data type | Shown as |
| --- | --- | --- |
| `DB10.4` | `real` | `DB10.DBD4` |
| `DB10.4` | `int` | `DB10.DBW4` |
| `DB10.4` | `byte`, `lreal`, `string` | `DB10.DBB4` |
| `DB10.4.0` | `bool` | `DB10.DBX4.0` |
| `M20` | `word` | `MW20` |
| `I0.3` | `bool` | `I0.3` |

The stored address does not change with the display.

## Tag options

`protocol_options` of a Tag. Unknown keys are refused.

| Key | Values | Notes |
| --- | --- | --- |
| `data_type` | `bool`, `byte`, `word`, `dword`, `lword`, `char`, `sint`, `usint`, `int`, `uint`, `dint`, `udint`, `lint`, `ulint`, `real`, `lreal`, `string`, `time` | Required |
| `length` | 1 to 254 | Required for `string` (the declared maximum length), refused for other types |
| `scale` | number other than 0 | Value is raw times scale plus offset. Not for `bool`, `char` and `string` |
| `offset` | number | As for `scale` |

## Data types and spans

S7 data is big-endian. There are no byte order or word order options.

| Data type | Bytes | Meaning | Value type |
| --- | --- | --- | --- |
| `bool` | 1 (one bit) | Bit | boolean |
| `byte`, `usint` | 1 | Unsigned 8-bit | integer |
| `sint` | 1 | Signed 8-bit | integer |
| `char` | 1 | One Latin-1 character | text |
| `word`, `uint` | 2 | Unsigned 16-bit | integer |
| `int` | 2 | Signed 16-bit | integer |
| `dword`, `udint` | 4 | Unsigned 32-bit | integer |
| `dint` | 4 | Signed 32-bit | integer |
| `time` | 4 | Signed milliseconds (S7 `Time`) | integer |
| `real` | 4 | 32-bit float | numeric |
| `lword`, `ulint` | 8 | Unsigned 64-bit | integer |
| `lint` | 8 | Signed 64-bit | integer |
| `lreal` | 8 | 64-bit float | numeric |
| `string` | `length` + 2 | S7 `String[length]` | text |

The Panel sets the Tag's `value_type` from these options. A Tag with `scale` or
`offset` is `numeric`. A Tag whose `value_type` does not match is refused on
save and on import.

An S7 `String` holds the maximum length in byte 0, the actual length in byte 1
and then the characters, decoded as Latin-1. An actual length above the
maximum gives a bad reading `s7_string_invalid`. A float that is NaN or
infinite, or scaling that gives a non-finite number, gives
`s7_value_not_finite`. An unscaled `lword` or `ulint` above 9223372036854775807
does not fit the 64-bit signed integer column and gives
`s7_value_out_of_range`; set `scale` to 1 to store it as a float.

S7 has no source timestamp; the time of the response is used.

## Block reads

Each poll reads neighbouring Tags in as few requests as possible. Tags are
grouped by area (and DB number), sorted by byte, and merged into one block while
the gap between them is at most `max_gap` bytes and the block fits in one
response. Overlapping Tags share a block. Several blocks are then packed into
one multi-item request. The limit is the PDU size the CPU agreed to at
connect, not a fixed number of items: a 240-byte PDU carries about 18 items.
A block too big for one response is split. Requests are sent one at a time.

`max_gap` 0 merges only contiguous or overlapping Tags. Raise it to read
through small holes with fewer requests. A merged block that reaches past the
end of a DB is refused by the PLC, and the driver falls back as described
below.

Each request is read within the smallest Tag Group timeout among its Tags. A
Tag Group timeout longer than the Connection timeout is honoured. Opening the
connection uses the Connection timeout. Addresses and options are parsed once
and the block plan is reused while the set of Tags is unchanged.

## Errors

A bad Tag never makes the other Tags of its Tag Group bad.

The PLC answers each item of a request with its own return code. When a block
that holds one Tag is refused, only that Tag is bad. When a block that merged
several Tags is refused, the driver reads its Tags one by one in the same
poll, so that only the Tags the PLC refuses go bad. When at least one Tag is
refused on its own, the driver remembers this and reads that block Tag by Tag
on later polls, until the Tags change (Apply) or the service restarts; it logs
`s7_block_split_remembered` at INFO, with the area, DB, start, length and
return code. When every Tag reads fine on its own, nothing is remembered and
the next poll tries the whole block again. If the message appears often,
lower `max_gap`.

| Error code | Meaning |
| --- | --- |
| `s7_invalid_tag` | The Tag's address or options do not resolve |
| `s7_db_not_found` | Return code 0A: the PLC has no such object. For a DB, the message reads "The PLC has no DB10 of this size. Check the DB number and offset; on S7-1200/1500 also switch off 'Optimized block access' in the DB's properties and download it." |
| `s7_address_out_of_range` | Return code 05: the address is outside the area. For a DB the message is the same as for `s7_db_not_found`; an optimized DB usually answers this way. For M, I and Q: "The PLC has no M20 of this size. Check the address." |
| `s7_access_denied` | Return code 03 for one item (protection level or PUT/GET), or the whole request was refused, see below |
| `s7_type_not_supported` | Return code 06: the PLC does not support reading this address |
| `s7_item_error_XX` | Any other return code, `XX` in two-digit uppercase hex. `s7_item_error_FF` means the PLC said "success" but returned fewer bytes than asked |
| `s7_string_invalid` | A `string` Tag has an actual length above its maximum |
| `s7_value_not_finite` | A float is NaN or infinite, or scaling gave a non-finite number |
| `s7_value_out_of_range` | An unscaled `lword` or `ulint` above 9223372036854775807 does not fit the signed 64-bit column |
| `s7_timeout` | A read timed out |
| `s7_connection_lost` | The connection failed during a read, or a response could not be read |
| `s7_connect_failed` | The connection could not be opened |
| `s7_not_connected` | A read was attempted without a connection |

The last four fail the whole poll: every Tag in that poll gets a bad reading
with the same code, and the worker reconnects as it does for OPC UA. After a
timeout or a lost connection the driver closes the link and repeats the same
error until the worker reconnects. The other codes belong to single Tags.

**PUT/GET refused.** When the PLC rejects a whole request, which an S7-1200 or
S7-1500 does while "Permit access with PUT/GET communication from remote
partner" is off, every Tag of that request gets `s7_access_denied` with the
message "The PLC refused the read. On S7-1200/1500: enable 'Permit access with
PUT/GET communication from remote partner' in the CPU's Protection & Security
settings, then download the hardware configuration." The connection is fine,
so the driver does not reconnect and does not re-read Tag by Tag. It keeps
polling at the usual interval and logs one WARNING, `s7_reads_refused`, until
a read succeeds. Fixing the setting in TIA recovers without restarting the
collector.

## Paste tags (CSV)

On a Connection's page, "Paste tags" creates many Tags from an address list
copied out of a spreadsheet. It works as for Modbus: a header line, the
separator (tab, semicolon or comma) taken from the header, at most 1000 rows
and 1 MB of text, a preview that shows every row, and an all-or-nothing save.

- The columns are `name`, `address`, `data_type`, `length`, `scale`, `offset`,
  `unit`, `tag_group` and `enabled`. Only `name`, `address` and `data_type` are
  required. `enabled` accepts yes or no (also true, false, 1, 0, on, off) and
  defaults to yes. Rows without a `tag_group` use the group chosen above the
  text box.
- `address` is in the canonical or any STEP7 form. A size letter that
  contradicts `data_type` is an error on that row.
- Two rows, or a row and an existing Tag, with the same area, DB, byte and bit
  are flagged as duplicates.

Example:

```text
name;address;data_type;length;scale;unit
Pressure;%DB1.DBD0;real;;;bar
Ram position;DB1.DBW26;int;;0,1;mm
Recipe;DB1.DBB36;string;20;;
Door closed;DB1.DBX4.2;bool;;;
Lamp;M0.0;bool;;;
```

## Tag form and fast entry

The Tag form has Area (Data block, Merkers, Inputs, Outputs), DB number (for a
data block), Byte, Bit (for `bool`), Data type and Length (for `string`);
Scale and Offset are under "Advanced". "Paste address" fills Area, DB number,
Byte and Bit from a STEP7 address, and sets the data type from its size letter
when none is chosen.

After "Save tag", the form opens again with the same Tag Group, area, DB
number and data type, and the address set to the next one: the byte plus the
Tag's span, or for `bool` the next bit, with bit 7 rolling over to bit 0 of the
next byte.

## Import from TIA Portal

On an S7 Connection's Tags page, "Import from TIA Portal" turns a TIA Portal
export into Tags: names, addresses, types and comments. The comment is stored
as the Tag's `description` and shown as a tooltip on the Tags list.

The importer calculates offsets, so a mistake would read the wrong bytes
without any error. It refuses what it cannot lay out with certainty, shows
every calculated offset in a preview, and saves nothing until you confirm.
Decision record: [ADR 0004](../adr/0004-tia-import-calculates-db-offsets.md).

### Option 1: a PLC tag table

For inputs, outputs and merkers that have names in TIA.

1. In TIA Portal, open the PLC tag table, choose Export, and save the `.xlsx`
   file.
2. In the Panel, choose "Import from TIA Portal", choose the Tag Group, and
   upload the file.
3. The preview lists each row. Rows with `%I`, `%Q` and `%M` addresses can be
   imported. Timers, counters, peripheral I/O (`:P`), rows without an address
   or type, and data types the driver does not read are listed with the
   reason. A selected row with a problem blocks the save until you clear it.

The sheet is read by header names (`Name`, `Data Type`, `Logical Address`,
`Comment`), not by position. The names are taken from TIA documentation; they
have not been checked against a real export.

### Option 2: data blocks

For the members of a DB, which have names but no offsets in a tag table.

1. In TIA Portal, select the data blocks in the project tree, right-click and
   choose "Generate source from blocks". Do the same for the PLC data types
   (UDTs) the DBs use. Save the `.db` and `.udt` files.
2. Switch off "Optimized block access" on the DBs first (see the checklist),
   compile and download, then export. A DB exported while optimized is
   refused.
3. Upload the `.db` files together with every `.udt` file they use.
4. The source names a DB, and sometimes states its number. Where it does not,
   the preview asks for the DB number as it is in TIA.
5. If a source has no `S7_Optimized_Access` attribute, it looks like a source
   from an S7-300/400, which has no optimized access. Tick "This DB is from an
   S7-300/400 (standard access)" for that DB to import it. Without the tick it
   is refused, so that an S7-1200/1500 source of unknown kind is never treated
   as standard.
6. Select the members you want. Arrays are expanded element by element and
   shown as one row with "select all elements". Edit the Tag names if you
   like.
7. Under each DB the preview says "Calculated size: N bytes. Compare a few
   offsets with the Offset column in TIA before saving." Do that: open the DB
   in TIA, show the Offset column, and compare a few members, including some
   after a Bool, a String, a Struct and an array.
8. "Import N selected tags" saves the selected rows.

### Offset rules

For DBs with standard access, as on the S7-300/400:

- A `Bool` takes one bit; consecutive Bools fill bits 0 to 7 of a byte.
- `Byte`, `Char`, `SInt` and `USInt` start at the next free byte.
- Every other elementary type, `String`, `Struct`, `Array` and UDT instance
  starts at the next even byte.
- A Struct, UDT or Array ends on an even byte. `Array of Bool` packs its bits.
- `String[n]` takes n + 2 bytes; a plain `String` is `String[254]`.

### What is refused

The importer names the file and line of the problem. It refuses:

- A DB with `S7_Optimized_Access := 'TRUE'`: "DB is optimized; switch off
  'Optimized block access' in TIA, compile, download, export again."
- A DB without the attribute that is not ticked as S7-300/400.
- An instance DB of a function block. A DB based on a PLC data type is
  imported when the `.udt` file is uploaded.
- A PLC data type that is not in the uploaded files, a type that contains
  itself, and any construct the parser does not know.
- `Variant`, `Pointer`, `Any` and `DB_ANY` members.
- An `Array` of `String[n]` with an odd `n`: where each element starts is not
  certain.
- A Struct or UDT with no members, nesting deeper than 64 levels, and a DB
  that passes byte 65535.

Members of types the driver cannot read (`Date`, `Time_Of_Day`, `DTL`,
`Date_And_Time`, `LTime`, `S5Time`, `WChar`, `WString` and similar) keep their
size, so the offsets of the other members stay right. They are shown greyed
with "Not supported in 0.5.0" and are not imported.

### Limits and behaviour

- At most 10 files of 5 MB each per upload, either one `.xlsx` or `.db` and
  `.udt` files, not both. At most 100 data blocks per upload.
- A tag table `.xlsx` may inflate to at most 50 MB and 100000 rows. XML with a
  DOCTYPE or entity declaration is refused.
- At most 1000 Tags per save. The save is all-or-nothing, with one audit
  entry per Tag.
- A row whose address is already used by another selected row, or by an
  existing Tag of the Connection, is flagged "Same address as ..." and blocks
  the save until you clear it.
- The files stay on the server only between the preview and the save, under a
  short-lived random token. An upload expires 30 minutes after it was last
  used, and is deleted after the save. The browser sends back only your
  choices; every preview and the save read the files again.
- Tag IDs are made from the names and are unique, as for the CSV paste.

## Simulator

`python -m plc_data_collector.simulators.s7` serves a press (DB1 "PressData",
68 bytes, standard access) and 16 merker bytes on port 1102, with values that
change over time. The rack and slot are not checked. The Docker Compose demo
starts it as `s7-sim`, and the demo configuration has a Connection
`press3_s7` for it (rack 0, slot 1).

The layout was worked out by hand, not generated by the importer, and the
source `deploy/demo/s7/PressData.db` (with `PressTypes.udt`) describes the
same DB, so you can try the import with it. A test checks that the importer's
offsets match this table.

DB1:

| Name | Type | Offset |
| --- | --- | --- |
| Pressure | real | 0 |
| Status.Running | bool | 4.0 |
| Status.Fault | bool | 4.1 |
| Status.DoorClosed | bool | 4.2 |
| Status.Mode | byte | 5 |
| Temps[0] | real | 6 |
| Temps[1] | real | 10 |
| Temps[2] | real | 14 |
| Temps[3] | real | 18 |
| Cycles | dint | 22 |
| RamPosition | int | 26 |
| Energy | lreal | 28 |
| Recipe | string[20] | 36 |
| Motor.Current | real | 58 |
| Motor.Speed | int | 62 |
| Motor.Running | bool | 64.0 |
| Motor.Overheat | bool | 64.1 |
| Batch | uint | 66 |

Values: `Pressure` bar, 150 plus or minus 20; `Temps` degC around 60;
`Cycles` +1 every 0.5 s; `Batch` +1 every 10 s; `Status.Running` and
`Status.Fault` swap for 5 s every minute; `Status.DoorClosed` is always true;
`Status.Mode` cycles 1, 2, 3; `RamPosition` is mm times 10 (use scale 0.1);
`Recipe` is `RCP-0042`.

Merkers: `M0.0` lamp (toggles every 5 s), `M0.1` always true, `M2` an `int`
(`MW2`), a signed sine from -100 to 100.
