# TIA import calculates DB offsets; optimized DBs are refused

The S7 driver reads a data block by byte offset, but the exports TIA Portal
offers for DBs ("Generate source from blocks", `.db` and `.udt` text) carry
names and types without offsets. The Panel's "Import from TIA Portal" therefore
calculates the offsets itself, with Siemens' memory layout rules for DBs with
standard (non-optimized) access: Bools pack into bits, byte-sized types start
at the next free byte, everything else starts at an even byte, and structs,
arrays and UDTs end on an even byte. A DB with optimized block access is
refused, and so is anything whose layout the importer is not sure of. The
preview shows every calculated offset, so the user can compare a few with the
Offset column in TIA before saving.

A wrong offset is the worst failure here: the Tag reads the wrong bytes and
nothing reports an error. The import prefers refusing, with a reason, to
guessing.

## Considered Options

- **Import TIA Openness or SimaticML XML.** Rejected because it needs TIA
  Openness scripting, which most users do not have. The exports used here are
  reachable from ordinary right-click menus.
- **Import only PLC tag tables (`.xlsx`).** Rejected because tag tables carry
  absolute addresses and need no calculation, but most process data lives in
  DBs, so it would miss the point of fast Tag entry. Tag tables are imported
  too, for I, Q and M.
- **Calculate offsets for optimized DBs as well.** Rejected because optimized
  DBs have no fixed offsets: the CPU chooses them, and the PUT/GET protocol
  cannot address them.

## Consequences

- The importer (`tia/`) owns the layout rules and is tested against worked
  examples from Siemens documentation and against the simulator's DB1, whose
  layout was written by hand and not generated by the importer.
- A DB without the `S7_Optimized_Access` attribute is what an S7-300/400
  source looks like. It is imported only after the user ticks "This DB is from
  an S7-300/400 (standard access)" for that DB, so a source of unknown kind from
  an S7-1200/1500 is never treated as standard.
- Refused: optimized DBs, instance DBs of function blocks, `Variant`, `Pointer`,
  `Any` and `DB_ANY`, missing UDTs, `Array of String[n]` with an odd `n`, and
  unknown constructs. Types with a known size that the driver cannot read are
  shown greyed with "Not supported in 0.5.0", and their size keeps the other
  offsets right.
- The upload is kept on the server only between preview and save, under a
  short-lived token. Every preview and the save parse the files again and trust
  only the user's choices.
- The comment from TIA goes to the Tag's `metadata.description`; no migration.
- 0.5.0 S7 support, including these offsets, has not been tested on real
  hardware. The release notes ask users to compare offsets and report
  mismatches.
