# PLC Data Collector 0.2.0 Release Notes

Release date: 2026-11-12

## Summary

PLC Data Collector 0.2.0 turns the 0.1.0 runtime components into a service that
runs end to end: OPC UA Connections are polled, Poll Results flow through the
Reading Queue and the Database Writer into PostgreSQL, and the Spool protects
them while the database is down. The release adds a Docker Compose demo stack
with an OPC UA simulator, continuous integration, and a new README.

## Breaking Changes

- The package, CLI and environment variable prefix were renamed to
  `plc_data_collector`, `plc-data-collector` and `PLC_DATA_COLLECTOR_`.
  Update imports, service definitions and environment variables.

## Compatibility

- Python: 3.12 or newer.
- Storage: PostgreSQL 17 (tested), SQLite as the fallback when no database URL
  is set.
- Real PLC connectivity: OPC UA through `asyncua`.
- Deployment: Docker Compose demo stack, or an external process manager.

## Release Validation

The release is validated by:

- full pytest suite, including tests against a real PostgreSQL,
- ruff linting,
- ruff formatting check,
- mypy strict type checking,
- third-party credits regeneration,
- a Docker smoke test: simulator, collector and PostgreSQL started with
  `docker compose`, worker state checked through the API, and good-quality
  readings confirmed to grow in `tag_readings`.

## Known Limitations

- OPC UA is the only real protocol driver.
- Configuration is a hand-edited JSON file; there is no web UI yet.
- The API is read-only and has no authentication.
- A Poll Result that cannot enter a full Reading Queue within the timeout is
  dropped and counted as a failed cycle.
- There is no data retention policy for `tag_readings`.
- Production PLC interoperability must be validated against target devices
  before deployment.
