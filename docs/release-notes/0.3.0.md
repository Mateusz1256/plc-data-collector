# PLC Data Collector 0.3.0 Release Notes

Release date: 2026-11-13

## Summary

PLC Data Collector 0.3.0 moves the configuration into the database and adds
the Panel, a password-protected web UI for managing Connections, Tag Groups
and Tags and for watching current Tag values. Saved changes take effect with
"Apply changes", which restarts collection inside the running process without
losing queued readings. Applications can read collected data through a
read-only REST API (`/api/v1`) with per-application API keys, or straight from
PostgreSQL through the schema documented in `docs/database-schema.md`. A global
retention setting deletes old readings.

## Breaking Changes

- The JSON config file is now only imported when the database has no
  configuration. Edit configuration in the Panel or import a file in Settings.
  Environment overrides of Connection fields
  (`PLC_DATA_COLLECTOR_CONNECTIONS__<ID>__<FIELD>`) apply only to that import.
- `RuntimeSettings.config_file` is optional.

## Upgrading from 0.2.0

- Migration 0003 runs automatically at startup.
- Plaintext protocol secrets move to the encrypted `secret_options` column
  on first start.
- 0.2.0 added and updated configuration rows from the file on every start but
  never removed them, so Connections, Tag Groups and Tags deleted from the
  file are still in the database. On the first 0.3.0 start, when the config
  file is set and valid, the collector makes the file the active
  configuration once: rows the file no longer has are archived (their stored
  readings stay readable), and stored passwords the file leaves out are kept.
  The log shows `configuration_upgrade_reconciled` with the counts. After
  that the file is not imported again.
- Without the config file, or with an invalid one, nothing is changed and the
  log shows `configuration_upgrade_unreconciled` as a warning on each start
  until the configuration is first changed. In that case review Connections
  in the Panel after upgrading and delete leftovers that are no longer in
  use.
- Set `PLC_DATA_COLLECTOR_ADMIN_PASSWORD` to turn the Panel on.
- Set `PLC_DATA_COLLECTOR_SECRET_KEY`, or back up the `secret.key` file the
  collector generates in its data directory. Without the key, stored protocol
  passwords cannot be decrypted and have to be entered again.

## Compatibility

- Python: 3.12 or newer.
- Storage: PostgreSQL 17 (tested), SQLite as the fallback when no database URL
  is set.
- Real PLC connectivity: OPC UA through `asyncua`.
- Deployment: Docker Compose demo stack, or an external process manager.

## Release Validation

The release is validated by:

- full pytest suite, including tests against a real PostgreSQL,
- ruff linting,
- ruff formatting check,
- mypy strict type checking,
- third-party credits regeneration,
- a Docker smoke test: simulator, collector and PostgreSQL started with
  `docker compose`, worker state checked through the API, good-quality readings
  confirmed to grow in `tag_readings`, a Panel sign-in, an API key created in
  the Panel, and current values and history read from `/api/v1`.

## Known Limitations

- OPC UA is the only real protocol driver.
- The Panel has one admin password and no user accounts.
- `/health/*`, `/api/runtime/*` and `/api/about` have no authentication.
- Every API key can read every Tag.
- Retention is global, one number of days for all Tags.
- A Poll Result that cannot enter a full Reading Queue within the timeout is
  dropped and counted as a failed cycle.
- Production PLC interoperability must be validated against target devices
  before deployment.
