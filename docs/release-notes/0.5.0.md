# PLC Data Collector 0.5.0 Release Notes

Release date: 2026-11-26

## Summary

PLC Data Collector 0.5.0 adds Siemens S7 as the third real protocol,
read-only. S7-300, S7-400, S7-1200 and S7-1500 CPUs are read by rack and slot
over ISO-on-TCP: data blocks, merkers, inputs and outputs, as `bool`, `byte`,
`word`, `dword`, `lword`, `char`, `sint`, `usint`, `int`, `uint`, `dint`,
`udint`, `lint`, `ulint`, `real`, `lreal`, `string` and `time`, with optional
scale and offset. Neighbouring Tags are read as one block, and several blocks
travel in one request, within the PDU size the CPU agreed to. One item the PLC
refuses never makes the other Tags of its Tag Group bad, and the error
messages name the likely S7-1200/1500 causes (PUT/GET off, optimized block
access on). The Panel has an S7 Connection form, a Tag form with fast entry and
a "Paste address" box, CSV paste with STEP7 addresses, and "Import from TIA
Portal", which creates Tags from a PLC tag table (`.xlsx`) or from data block
sources (`.db` and `.udt`) with calculated offsets
([ADR 0004](../adr/0004-tia-import-calculates-db-offsets.md)). The demo stack
includes an S7 simulator. See [the S7 guide](../protocols/s7.md).

**S7 support is not tested on real hardware.** There was no real S7 PLC for
this release. The driver is verified against the python-snap7 server, byte-level
protocol fixtures and the simulator, and the import's offsets against worked
examples from Siemens documentation and the simulator's hand-written layout.
The tag-table column names are taken from TIA documentation, without an
export from a real TIA Portal. Before trusting an import, compare a few
offsets with the Offset column in TIA. Please report mismatches.

## Breaking Changes

None.

## Upgrading from 0.4.0

- There is no migration; the schema stays at migration `0004`.
- The new runtime dependency is `python-snap7` 3.6.0 (MIT, pure Python).
- The imported TIA comment is stored in the Tag's `metadata` as
  `description`. The REST API and the JSON export are unchanged in shape.
- OPC UA and Modbus Connections and Tags are not affected.

## Rolling back to 0.4.0

There is no migration to undo, so 0.4.0 runs on the same database. S7
Connections and Tags stay in it, but 0.4.0 has no driver for them. Archive the
S7 Connections before you roll back.

## Compatibility

- Python: 3.12 or newer.
- Storage: PostgreSQL 17 (tested), SQLite as the fallback when no database URL
  is set.
- Real PLC connectivity: OPC UA through `asyncua`; Modbus TCP through
  `pymodbus` 3.16.2; Siemens S7 through `python-snap7` 3.6.0 for the
  connection, with the project's own read-request codec. S7 and Modbus are
  read-only.
- Deployment: Docker Compose demo stack, or an external process manager.

## Known Limitations

- S7 is not tested on real hardware (see the Summary).
- S7 is read-only; the collector never writes to a PLC. Connections are by
  rack and slot only: no LOGO!, S7-200, routed connections, S7CommPlus or TLS.
- DBs with optimized block access cannot be read. On S7-1200/1500, switch it
  off per DB, and enable PUT/GET access in the CPU's settings.
- No timers, counters or peripheral I/O. Date and time types other than `time`
  (`Date`, `DTL`, `Time_Of_Day`, `LTime` and similar), `WString` and `WChar` are
  not read; the TIA import shows them greyed.
- The TIA import refuses instance DBs of function blocks, `Variant`,
  `Pointer`, `Any`, `DB_ANY` and `Array of String[n]` with an odd `n`.
- Saving a large CSV paste or TIA import writes one audit entry per Tag.
- The Panel has one admin password and no user accounts.
- The sign-in throttle (5 failed attempts in 5 minutes) counts per client IP
  address. Behind a reverse proxy every user arrives from the proxy's
  address, so all users share one limit, and failed attempts by one person
  lock out everyone for a few minutes.
- `/health/*`, `/api/runtime/*` and `/api/about` have no authentication.
- Every API key can read every Tag.
- Retention is global, one number of days for all Tags.
- A Poll Result that cannot enter a full Reading Queue within the timeout is
  dropped and counted as a failed cycle.
- Production PLC interoperability must be validated against target devices
  before deployment.
