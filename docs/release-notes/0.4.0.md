# PLC Data Collector 0.4.0 Release Notes

Release date: 2026-11-20

## Summary

PLC Data Collector 0.4.0 adds Modbus TCP as the second real protocol, read-only.
Coils, Discrete inputs, Holding registers and Input registers can be read as
`bool`, `bit`, 16, 32 and 64-bit integers, `float32`, `float64` and `string`,
with byte order, word order, unit ID, scale and offset set per Connection and
overridable per Tag. Neighbouring registers are read in blocks, and one
register the device refuses never makes the other Tags of its Tag Group bad.
The Panel has a Modbus Connection form and a Tag form with fast entry, and
"Paste tags" creates many Tags at once from CSV. To support this, Tags have
structured `protocol_options` ([ADR 0003](../adr/0003-protocol-tag-settings-are-structured-options.md)).
The demo stack includes a Modbus simulator. See [the Modbus guide](../protocols/modbus.md).

## Breaking Changes

None.

## Upgrading from 0.3.0

- Migration 0004 runs automatically at startup. It adds `tags.protocol_options`
  (existing Tags get `{}`).
- Tag objects in the JSON export and in the REST API (`/api/v1`) gain
  `protocol_options`. Exports from 0.3.0 import unchanged.
- OPC UA Connections and Tags are not affected.

## Rolling back to 0.3.0

Stop 0.4.0 and run `alembic downgrade 0003` against the database (with the
0.4.0 package's migrations), then start 0.3.0. The downgrade drops
`tags.protocol_options`. Modbus Connections stay in the database, but 0.3.0
has no driver for them, and Modbus Tag settings (data type, byte and word
order, unit ID, scale, offset) are lost. Archive the Modbus Connections before
you roll back.

## Compatibility

- Python: 3.12 or newer.
- Storage: PostgreSQL 17 (tested), SQLite as the fallback when no database URL
  is set.
- Real PLC connectivity: OPC UA through `asyncua`; Modbus TCP through
  `pymodbus` 3.16.2. Modbus is read-only.
- Deployment: Docker Compose demo stack, or an external process manager.

The release is validated by:

- ruff linting,
- ruff formatting check,
- mypy strict type checking,
- third-party credits regeneration,
- a Docker smoke test: simulators, collector and PostgreSQL started with

  reaching `tag_readings` with good quality), a Panel sign-in, an API key

## Known Limitations

- No Modbus RTU over serial and no Modbus/TCP Security (TLS).
- Modbus is read-only; the collector never writes to a device.
- Devices that reject reads of undefined registers need `max_gap` 0, the
  default.
- Saving a large CSV paste writes one audit entry per Tag.
- The Panel has one admin password and no user accounts.
- The sign-in throttle (5 failed attempts in 5 minutes) counts per client IP
  address. Behind a reverse proxy every user arrives from the proxy's
  address, so all users share one limit, and failed attempts by one person
  lock out everyone for a few minutes.
- `/health/*`, `/api/runtime/*` and `/api/about` have no authentication.
- Every API key can read every Tag.
- Retention is global, one number of days for all Tags.
- A Poll Result that cannot enter a full Reading Queue within the timeout is
  dropped and counted as a failed cycle.
- Production PLC interoperability must be validated against target devices
  before deployment.
